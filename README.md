# GIGA — сайт ИИ-персонажей

Проект собран на основе мобильного HTML-интерфейса и ресурсов из предоставленного ZIP. Интерфейс и исходные изображения сохранены; демонстрационные вход, ежедневные кристаллы и фальшивый ответ чата заменены серверными интеграциями.

## Что реализовано

- Адаптивный мобильный интерфейс на основе `public/index.html` и оригинальных `public/assets/`.
- Firebase Authentication: Google и SMS/телефон.
- Проверка Firebase ID token на сервере через Firebase Admin SDK.
- Ежедневное начисление 50 кристаллов на сервере.
- Защита от повторного получения в тот же день: уникальная запись `firebase_uid + claim_date` в MySQL и транзакция.
- История чатов и созданные персонажи в текущем браузере (localStorage).
- Реальные ответы GigaChat-2 через серверный endpoint.
- Системный промпт берётся из `GIGACHAT_SYSTEM_PROMPT` на сервере и не передаётся в браузер.
- API-ключ GigaChat и Firebase service account остаются на сервере.

## Запуск

1. Установи Node.js 20 или новее и MySQL 8.
2. Создай пустую базу данных, например `giga_site`, и пользователя с правами `CREATE`, `SELECT`, `INSERT`, `UPDATE`.
3. Скопируй `.env.example` в `.env` и заполни значения.
4. Установи зависимости:
   ```bash
   npm install
   ```
5. Запусти:
   ```bash
   npm start
   ```
6. Открой `http://localhost:3000`.

Таблицы `giga_credit_accounts` и `giga_daily_claims` создаются автоматически при запуске сервера. Если сервер не может подключиться к MySQL, он не стартует — это сделано намеренно, чтобы не выдавать фиктивный баланс.

## Настройка Firebase

В Firebase Console для проекта `giga-9c2e2`:

1. Authentication → Sign-in method: включи Google и Phone.
2. Authentication → Settings → Authorized domains: добавь домен сайта и `localhost` для локального теста.
3. В Project settings → Service accounts создай service account credentials.
4. Сохрани JSON service account в секретах хостинга как `FIREBASE_SERVICE_ACCOUNT_JSON` (или base64 как `FIREBASE_SERVICE_ACCOUNT_JSON_BASE64`). Не загружай файл в `public/`, Git или ZIP для публикации.
5. Для SMS проверь разрешённые страны/регионы и лимиты Firebase Authentication.

Firebase Web API config внутри `public/index.html` — публичная конфигурация клиентского приложения. Это не service-account ключ. Защита обеспечивается проверкой ID token сервером и настройками Firebase Authentication.

## Настройка GigaChat-2

1. Получи API credentials в кабинете GigaChat API.
2. Добавь Basic credentials в серверную переменную `GIGACHAT_API_KEY`.
3. Оставь `GIGACHAT_MODEL=GigaChat-2`.
4. Задай собственный системный промпт в `GIGACHAT_SYSTEM_PROMPT`. Он хранится только в переменных окружения сервера.
5. Перезапусти сервер.

Если ключ отсутствует или API не отвечает, сайт покажет ошибку. Заготовленные ответы вместо ИИ не используются.

## Ежедневные кристаллы

Сервер начисляет 50 кристаллов после подтверждённой авторизации. Один бонус на аккаунт за UTC-календарную дату. Клиент не может самостоятельно менять баланс: начисление выполняется транзакцией MySQL, а уникальный индекс не позволяет повторить бонус в тот же день.

## Публикация

Размести Node.js приложение на хостинге, который поддерживает Node.js 20+, HTTPS и MySQL. Настрой переменные окружения из `.env.example`, укажи домен в Firebase Authorized domains и направь домен на порт приложения через настройки хостинга/reverse proxy. Для публичного сайта обязательно используй HTTPS.

## Что ещё требуется от владельца проекта

- Заполнить секреты `GIGACHAT_API_KEY` и `FIREBASE_SERVICE_ACCOUNT_JSON` в панели хостинга.
- Подключить MySQL базу.
- Проверить домен в Firebase и реальную отправку SMS.
- Убедиться, что выбранный тариф GigaChat API разрешает нужную модель и объём запросов.

## Ограничения текущей версии

- Переписки и пользовательские персонажи пока сохраняются локально в браузере, а не синхронизируются между устройствами.
- Магазин кристаллов в исходном интерфейсе остаётся демонстрационным; платежи не подключены.
- Системный промпт скрыт на сервере, но пользовательские описания персонажей вводятся пользователем и отправляются серверу как настройки конкретного персонажа.
- Дата ежедневного бонуса считается по UTC, поэтому смена дня происходит в 00:00 UTC.
